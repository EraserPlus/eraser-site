开发交接

这一页写给「接手的下一个人 / 下一个 AI」：读完它，你就能接着开发这个小站，不踩坑、不断线。

🤖 你是接手的 AI？先做三件事： ① 读完全页（大约 3 分钟）；② 找到本机工作副本，对照「工作流程」第 1 步核对版本；③ 向站长确认本次要做什么，然后照「工作流程」六步执行。不确定的地方参考「红线与约定」，别自由发挥。

0. 一句话认识这个站

Eraser 的个人小站：不面向公众、无商业、单人使用，一切取舍以「一个人用起来省事」为准。现在是：搜索（首页） / 工具箱 / 博客 / 追更 / 导航 / 关于 六个前台页面 + 一个带 7 个标签的后台。

2. 工作流程（六步，别跳步）

  1. 对齐 —— 找到本机工作副本（在 C 盘 WorkBuddy AI 目录下搜索 .repo/eraser-site，找不到就问站长）。不要乱 git reset：本机 clone 的 HEAD 停在远古分支，git status 大多是无意义的噪音；可靠做法是「blob 逐一比对」（见第 3 节末尾的附注）。
  2. 改动 —— 小步改，遵守「红线与约定」。数据库 schema 能不动就不动（content 表 jsonb 存字段，加内容类型无需建表）。
  3. 测试 —— npm test 七套全绿。新功能必须带新测试，不绿不提交。
  4. 推送 —— 本机 git push 直连不通，用仓库里的脚本走 GitHub API 推送（见下方「环境特殊性」）。推送后创建 PR。
  5. 上线 —— 等 PR 的 CI 和 Vercel 检查全绿 → 合并 → 等 1~2 分钟 → 线上实测（curl 状态码 + 浏览器/无头 Chrome 看真页面）。
  6. 收尾 —— 回来更新本页：批次记录加一行、当前版本号、当前待办。这是硬性规矩，不是可选项。

3. 本机环境特殊性（不遵守会卡死）

这台机器的坑，先记住再动手： ① git push 直连不通（schannel 证书吊销检查，改配置也无解）→ 用 dev/push-branch.sh 脚本走 gh CLI 推送；git fetch 同样不通，看线上状态一律用 gh api；② Node 不能创建子进程（spawnSync 报 EBUSY）→ 别写需要子进程的脚本，截图用「Bash 起 Chrome + Node 连 CDP」模式；③ 禁止 npm install（会把 node_modules 里的假驱动冲成真包，测试全挂），只允许 npm install --package-lock-only；④ 测试用的假驱动在 tests/stubs/（Neon 与 Vercel Blob 的手写 stub），本地和 CI 都不连真服务；⑤ PowerShell 常常拿不到 stdout → 让命令把结果写进临时文件，再用 Read 读；⑥ git hash-object / sha1sum 在 Git Bash 里会被 SIGTERM → 在 PowerShell 里手搓 git blob SHA；⑦ 写 TSV/粘贴的清单容易带上 BOM → 用 Python 以 utf-8-sig 读、以 utf-8/LF 写回；⑧ gh pr create 有时会以 SIGTERM 退出但 PR 其实已经建好了 → 别重试，先 gh pr list --head <分支> 确认。

推送与提交（第 4 步的具体做法）

# 1) 写提交清单 manifest.tsv（每行：A/M/D + Tab + 文件路径，相对仓库根）
#    A 新增 / M 修改 / D 删除，只列本次要提交的文件

# 2) 推送分支（git push 不通，走脚本）
COMMIT_MSG="批次名：一句话说明" bash dev/push-branch.sh <分支名> <manifest.tsv> main

# 3) 创建 PR
gh pr create -R EraserPlus/eraser-site --base main --head <分支名> \
  --title "..." --body-file <PR 正文文件>

脚本参数：先 DRY_RUN=1 演练一遍更稳；gh 子命令记得带 -R EraserPlus/eraser-site。

附注：核对工作副本与线上是否一致（第 1 步的完整做法）

拿 main 的每个文件 blob SHA 与本地 git hash-object 逐一比对，差集基本只有你本次的改动；反向再用 comm -23 找「本地多出、线上没有」的文件（历史残留，别误提交）。

# 拉 main 全量文件清单（path + blob SHA）
gh api "repos/EraserPlus/eraser-site/git/trees/main?recursive=1" \
  --jq '.tree[] | select(.type=="blob") | .path + "\t" + .sha' > /tmp/main_tree.tsv

# 逐文件比对
while IFS=$'\t' read -r path sha; do
  if [ -f "$path" ]; then
    [ "$(git hash-object "$path")" != "$sha" ] && echo "DIFF  $path"
  else
    echo "MISS  $path"
  fi
done < /tmp/main_tree.tsv

4. 红线与约定（改之前必须知道）

  • 不换框架、不引构建步骤、不拆大单文件（nav/index.html、admin/index.html 都是刻意保持的单文件——「双击能开、断网能看」是核心资产）。
  • 公开页静态兜底硬规则：先渲染写死内容 → 再 fetch 同源 API 覆盖 → 失败保持静态，永不白屏；空数据显示空状态提示。
  • 防注入：前台页用 DOM API + textContent 构建列表；md.js 转义三铁律（先整体 esc 再生成标签 / 已转义不再二次 esc / URL 过白名单）。
  • PATCH 全是合并语义：只更新请求体里出现的字段；清空要显式传 null。
  • 行尾 LF、UTF-8 无 BOM；新文件写完顺手检查。
  • 敏感信息绝不进仓库：密码、令牌只在 Vercel 环境变量里。仓库是公开的。
  • 主题机制：每页 <head> 有一段防闪内联脚本，首帧前把 eraser.theme（没存过就跟随系统偏好）写到 html[data-theme]；暗色样式一律写成 html[data-theme="dark"] 选择器，不要再写 @media (prefers-color-scheme: dark)。顶栏按钮与 Ctrl+K 面板由 shell.js 提供（后台另有自己的 eraser.admin.theme，互不影响）。
  • 每批独立提交、独立可回滚（git revert 即可）；测试全绿才合并。

给 AI 用的一套闭环（M10 主线A，站长目前最想要的东西）

站长原话：「给我一个可以提供 API 的接口，然后 AI 就可以帮我生成对应的知识图」。所以做成了：后台点一下拿配置 → 贴给 AI → AI 建图 / 打卡 / 查漏补缺。

拿配置后台「学习」标签最上面 → 生成 / 换一条令牌 → 复制接入配置，整段贴给 AI 即可。或直接调 GET /api/ai?guide=1 拿一份完整 Markdown 说明书。
令牌管理GET /api/ai 读状态（是否已发、签发时间、世代号）/ POST /api/ai 发新令牌 / DELETE /api/ai 一键吊销（世代 +1，全部作废）。这三个都要后台令牌，AI 令牌不能管理自己。
两种令牌后台令牌：30 天，前缀 eraser-admin-token-v1::；AI 令牌：365 天，前缀 eraser-ai-token-v1::，payload 带 kind:'ai' 和 ep。签名密钥不同，互不通用——吊销 AI 令牌不会把站长的后台登录踢掉。
查漏补缺GET /api/learn?gaps=1（可带 &id=）直接给结论：每组 state（not_started/in_progress/done）、untouchedGroups（从没动过）、stalledGroups（落后了）、suggest[]（建议先补哪几个节点）。不带 id 时给全部地图 + totalLeft + needFirst。
门槛设定api/ai.js 用 requireAdmin()；api/learn.js 写操作读 meta.ai_epoch 后走 requireAny()。改令牌逻辑务必同时看 api/_lib/token.js 和这两个调用点。

AI 助手接学习地图（M9 给外部 AI 用的接口）

站长要的是「我接上 API，它就能帮我管理学习地图、建图、查漏补缺」。接口刻意做成节点粒度——AI 勾一个节点不用把整张地图重发一遍。

鉴权后台令牌或 AI 令牌都可以（requireAny）；GET 全部免登录（前台页面要读）。
只读GET /api/learn 列全部地图（含进度概览，不带 nodes，省流量）；GET /api/learn?id=123 读一张地图（含节点 + 按分组的进度明细 progress.groups）；GET /api/learn?gaps=1 查漏补缺快照。
地图级POST /api/learn 新建（{title, desc?, status?, nodes?}）；PATCH /api/learn 改信息（合并语义：不传 nodes 就原样保留）；DELETE /api/learn?id=123。
节点级POST /api/learn?action=addNode {id, node:{text, group?, note?}}；action=updateNode {id, nodeId, patch}；action=removeNode {id, nodeId}；action=toggleNode {id, nodeId}；action=setNodes {id, nodes:[…]}（重排整表）。
节点结构{ id, text, group, done, note }。id 只允许 [a-zA-Z0-9_-]、地图内唯一；缺 id 时按位置兜底生成 n1/n2…；单图上限 500 节点。传错 nodeId 会 400 并列出这张地图现有的 id，方便 AI 自我纠正。
返回写操作一律返回 { ok, item, progress }，progress 含 total / done / left / percent / groups[]——AI 不必自己算进度。

全站搜索的取舍（M9 定的，别改回去）

站长明确要求「搜索别太乱」。本站是索引型站点，正文命中会把结果冲垮——搜「Vercel」时十几篇文章只要正文提过就全冒出来。现在的规矩：

  • 搜的范围只有标题 / 摘要 / 标签 / 关键词级别的字段；
  • 博客文章：title / summary / tags，不含 content；
  • 页面：只有 title，不含 content；
  • 学习地图：title / desc，不含节点的 text（搜地图里的字是站长明令禁止的）；
  • 关键词不足 2 个字符直接返回空并带 tooShort，前端提示「再打一个字」。

回归测试里写死了这几条（api_routes_test.mjs 的「收窄搜索范围」段会断言 SQL 里不出现 data->>'content' 和 nodes）。要放宽必须先想清楚为什么。
